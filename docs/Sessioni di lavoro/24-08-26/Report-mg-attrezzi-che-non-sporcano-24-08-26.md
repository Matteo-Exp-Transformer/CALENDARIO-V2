# Report — M-G: attrezzi che non sporcano il corpus — 24-08-2026

**Modalità:** deep · **Ruolo:** orchestratore senior · **Stato:** **PROVATO, non CHIUSO**

## 1. Cappello

- **Cosa è cambiato:** una capsula distingue l'exit atteso, un comando Windows probabilmente malformato avvisa, un verificatore non può contraddirsi e la checklist non accusa più l'owner per un Git senza commit.
- **Cosa resta:** una controverifica di famiglia diversa per la chiusura formale; poi `M-F`.
- **Serve una tua azione:** no.

## 2. Cosa è stato fatto

`N3` e `N4`: `--check-expect` si lega al controllo immediatamente precedente; il record dichiara exit reale e atteso. Un path Windows con spazi non quotato o con apici singoli avvisa senza bloccare; le virgolette doppie restano pulite.

`N5`: la porta `--verify` accetta solo gli stati coerenti con un verificatore. Il validator applica la stessa regola anche dopo gli amendment, quindi non esiste una seconda strada per dati incoerenti.

`N6`: `mss:doctor` giudica l'owner dal solo blocco owner di `mss:status`, non dalla sezione Git. Una repo appena inizializzata non produce più un falso rosso owner.
